# webui

A rough local bench for watching poke-routes build a route, stage by stage, drawn with Emerald's General + Fortree metatiles. Beach, desert, mountain and volcanic routes use their own learned model and tileset (Slateport, Mauville, Lavaridge, Fallarbor; see `pokeroutes/models/index.json`). With the PokeRoutes tiles picked they use those instead: sand gets a wet-sand and foam shore where it meets water, rivers get wooden bridges, and falls between water to the west and east cascade sideways. The atlas for those is `/api/atlas?ts=<tileset>`.

Run: `python3 webui/server.py`, then open http://localhost:8790 (stdlib server; set `PORT=` to change the port).

## Editor shell (rough)

The page is laid out like a small game-engine editor (Unity's dark theme was the reference): a menu bar, a toolbar, docked panels you can resize or collapse, and a status bar. It replaced the old one-page bench after the owner found that hard to use. `/index.html` and `/region.html` now redirect to `/`.

- **Menu bar**: File (new route, open/save spec as JSON, open YAML specs too, recent routes, import, export: Porymap zip, scene.json, PNG of the current stage, region JSON, all region specs), Edit (undo/redo of spec edits and paint strokes, copy/paste spec, preferences), View (panels, zoom, frame selection, overlays, which stage to show), Generate (generate, new seed, region, tiler: learned or PokeRoutes tiles, stage stepping; PokeRoutes is the default when the server has the PokeRoutes tilesets, because Emerald's sheet hid the bottom bank of ponds under trees, and a saved Learned only sticks if it was picked by hand), Window (scene / geography / region views, console, timeline, Improve, reset layout), Help (shortcuts, about). Menus show Cmd on macOS and Ctrl elsewhere.
- **Shortcuts** are all in `SHORTCUTS` in `static/shell-logic.js`. Single keys (Space, arrows, V/H/B/S tools, F frame) only work when no text field or slider has focus. Generate is Cmd/Ctrl+G and never fires from a text field; the old Ctrl+Enter is gone.
- **Layout**: Hierarchy on the left (exits, lanes, special areas, clearings and lakes, items and events, layers with visibility toggles; click selects, double-click frames). The centre has Scene / Geography / Region tabs. Inspector on the right, full height: the selected object, then the spec fields in foldouts, the route report and the encounter tables. The bottom dock has Console (log, warnings, generation report), Timeline (stage ruler with change keys, plus zones and items added per stage) Improve and Agent. Hierarchy, Inspector and the bottom dock can also be torn off Unity-style: drag a panel's tab strip to make it a floating window you can move around and resize from its corner; drop it back on its own screen edge (a blue box shows where it lands), double-click its tab strip or press its corner button to dock it again. They only dock back to their own edge for now, not to each other's. Panel sizes, open/closed and floating docks, tabs and foldouts are kept in localStorage (`pokeroutes-shell-layout-v1`); Window > Reset layout clears them.
- **Tools**: select/pan, paint (classes) and stamp (tree block, pond, grass patch...); see "Bench paint" below.
- **Geography / Region tabs**: one region editor (below), split by job. Geography has the terrain tools (raise, lower, flatten, smooth, biome, coast) and moving legendary spots; routes are hidden there. Region has towns, routes (select, drag, add route) and a Routes list (Hierarchy in the shell; double-click flies the map to a route); double-click a route to load its spec and region block into Scene and generate it. Both tabs show the same map document, only the tools change. In the shell the editor no longer sits in a frame with its own toolbar and side panel (the owner called that a UI inside a UI): its map fills the centre view, its tools sit in the shell toolbar, its places and layers in Hierarchy, its panels in Inspector folds, its messages in the Console, and Generate, zoom, Undo/Redo, Save (File > Save region / Open saved region) go through the shell's own toolbar and menus. This replaced the read-only region picture and the World tab (the full editor in a frame, which the owner found confusing as a second copy of the same map). `/editor.html?mode=geography` or `?mode=region` does the same on its own page; no `mode` shows every tool. Placing Pokémon by hand isn't there yet; the route inspector only has `special_area_chance`.
- **Story tab and route gates** (added after the owner asked for generation to go geography -> route design A -> story -> route design B; Routes A is now labelled **Map**, and Routes B was folded back into it): **Story** is a hand-written list of beats in play order (name, the town or route it happens at, the field move it gives); beat 1 is where the game starts, and a beat whose place you can't reach with the moves from the beats before it gets a warning. Each route's gate is set in the Map tab's route inspector, under Gate: `needs` (Cut, Surf, Strength, Rock Smash, Waterfall, Dive; sea routes need Surf unless set) and `opens after` a beat (someone in the way until then); gated routes say so on the map ("needs Strength"). The separate Routes B tab and its story-step slider are gone; a saved shell layout that was on it opens Map. Beats live in the region document as `story`, gates on each route as `gate` (setting one pins the route); the gate is copied into the exported route spec, but the route generator doesn't place the Cut tree / boulder at the entrance from it yet, which is the obvious next thing to try. `/editor.html?mode=story` works on its own too (`?mode=gates` now opens the map).
- **Story / Routes B tabs** (added after the owner asked for generation to go geography -> route design A -> story -> route design B): Region is now labelled **Routes A** (the routes the generator lays on the geography). **Story** is a hand-written list of beats in play order (name, the town or route it happens at, the field move it gives); beat 1 is where the game starts, and a beat whose place you can't reach with the moves from the beats before it gets a warning. **Routes B** sets per route what it takes to get on it: `needs` (Cut, Surf, Strength, Rock Smash, Waterfall, Dive; sea routes need Surf unless set) and `opens after` a beat (someone in the way until then). A story-step slider colours routes green if you can walk to them at that point, red if not. Beats live in the region document as `story`, gates on each route as `gate` (setting one pins the route); the gate is copied into the exported route spec (and into its `region` block, so Open in Scene and Generate carry it).
  - **Gates in the generated route** (first try, `pokeroutes/gates.py`, the last generator stage): near the gated entrance the main path gets a Cut tree in a 1-wide gap of trees, a smashable rock or a Strength boulder in a 1-wide gap (the boulder only where a few straight pushes clear it), a band of water you have to Surf, or a water band with a waterfall step in it. "Opens after" puts someone in a 1-wide gap; the Porymap export gives them `FLAG_ARK_<MAP>_STORY_GATE_OPEN` and a script note "moves after <beat>" to wire up by hand. Dive isn't built: the route stays open and the log says so. The gap sits on a walking-distance layer from the entrance, so nothing walks round it; each try is checked (no way through without the move, everything still reachable with it) before it is kept, and the Scene log / report says what was placed or why nothing was.
  - **Which entrance**: the exit you walk up to first. With the route closed, play the story forward (new game, beat 1, 2, ...); the first step at which the place behind one of its exits can be reached decides it (ties: fewest road hops from the story's first town). No story, or nothing reachable through it: the exit fewest road hops from the first town, then exit 1 (`pokeroutes/region/gates.py`). The choice and the reason ride in the spec as `gate.entrance`, `entrance_toward` and `entrance_rule`.
  - Still rough: the gate is always about 4 steps in from the edge; waterfalls on an east-west path come out sideways; the gap walls are lone tree cells, which the tiler draws thin. `/editor.html?mode=story` and `?mode=gates` work on their own too.
- Files: `static/shell.html`, `shell.css` (theme), `shell.js` (menus, docks, console, keys), `bench.js` (scene, inspector, hierarchy, timeline, the editor frame, files), `shell-logic.js` (pure: shortcuts, layout maths, undo, recent list, spec conversion), `webui/shell_api.py` (entry page, redirects, PokeRoutes atlas, scene/spec exports, spec parsing).
- Tests: `node webui/tests/shell-logic.test.js`.

Extra API: `GET /api/tilers`, `GET /api/atlas?tiler=ark` (+ `.png`), `POST /api/generate {..., tiler: "ark"}`, `GET /api/scene?id=`, `GET /api/region-specs.zip?seed=`, `POST /api/spec-parse {text}`.

## Play-test window (first try)

The gamepad button next to Generate (or Window > Tools > Play-test) covers the Routes view with a 15x10-tile GBA screen and drops Brendan (read from a ROM tree on this machine; a plain marker if none has him) at the south exit. Arrows or WASD walk tile by tile, holding X or Shift runs, Z / Space / Enter is A, Esc closes; − and + change the integer zoom. Collision is the tiled layout's real collision bits plus the class grid: ledges hop one way (with the shadow), water needs the Surf toggle, waterfalls need Waterfall, Cut / Rock Smash clear their objects with A, Strength pushes boulders. Signs and people show the text the Porymap export writes, items and hidden items pop a small toast, and each step in tall grass rolls the Emerald land table ("Wild PIDGEY appeared!", no battle). Tile animation and the route effect particles keep playing. Walking off an exit that leads to another route in the open region opens that route through the same path as the Routes view's exit labels and keeps playing from the exit back; towns and unlinked exits just say so.

- Files: `static/playtest.js` (screen, input, drawing), `static/playtest-logic.js` (pure: steps, ledges, surf, field moves, encounters, camera, arrival), `static/playtest.css`, `webui/playtest_api.py` (`GET /api/playtest/route?id=` collision rows and sign/person text, `GET /api/playtest/sheet.png?pose=walking|running|surfing|surf_blob|tall_grass|jump_shadow`). Bench hands it a few hooks as `Bench.playtest_hooks`.
- Still rough: no bike, no NPC movement, sign events have no signpost metatile, so they get a small drawn post; the player always starts at the south exit, which on some seeds is behind a one-way ledge.
- Tests: `node webui/tests/playtest-logic.test.js`, `python3 -m pytest -q webui/tests/test_playtest_api.py`.

## Improve box (rough, unattended)

An attempt at Patrick Collison's "liquid software" idea: the **Improve** tab in the editor's bottom dock (or a small floating button on any other page that includes `static/improve.js`) is where you type how the software should be different. The server queues it and runs Claude Code headless on it, and the run logs stream into the panel.

- **Screenshot** freezes the page, then you drag a box anywhere on it and that box gets attached. **Mark up** freezes it too, you draw on it in red, then attach either the area around the drawing or the whole page. Both go through the browser's tab-share prompt. Each press adds another thumbnail (up to 6, × drops one), and the job gets all of them as `<id>.png`, `<id>-2.png`, ... in `improve-logs/`.
- **Parallel workers** (rough, added after the queue got long): 3 by default, 1-6 with the − / + next to "Workers" in the panel, or `IMPROVE_WORKERS=n` at start. Each slot shows its job; click one to see its log. A poke-routes job gets its own worktree `../poke-routes-wt/job-<id>` on branch `improve/job-<id>` made from main, and verifies with its own server copy on port 8800 + slot. When it has committed, a merge step (one at a time) rebases the commit onto the latest main and fast-forwards main, then fast-forwards the repo-root checkout the server serves from. If the root has uncommitted edits to the same files it waits 2 min, then moves main anyway and catches the checkout up on a later merge (the panel says so). A rebase conflict aborts and re-runs the job once on fresh main; a second conflict marks it `conflict` and keeps the branch to look at. Worktrees are removed afterwards.
- Statuses: queued, running, merging, done, conflict, failed, cancelled, undone (plus no-change, timeout).
- Targets: **Generator & web UI** (this repo) or **ROM** (`arklarna/rom`). ROM jobs work in a fresh worktree `../rom-wt/improve-<id>` on branch `arklarna/improve-<id>`, must build (`make -j10`) and be screenshotted with `tools/romshot`, and only then get squash-merged into `arklarna` and copied to `release/v1/arklarna-v1.gba`. Only one ROM job runs at a time (builds are heavy on this 8 GB machine), and no job starts while free + inactive memory (`vm_stat`) is under ~0.8 GB (`IMPROVE_MEM_MIN_MB`).
- Every job should end in exactly one commit starting with `improve: `. **Undo** queues a revert: for poke-routes it is made in a worktree and goes through the same merge step; for the ROM it reverts on `arklarna`, rebuilds and recopies the release ROM.
- **One owner**: only one server process runs workers. It holds an `fcntl` lock on `webui/improvements.json.lock` (with its pid and port in it). Any other copy of the server shows the queue read-only and passes submit / undo / cancel / workers on to the owner; if the owner dies, another running copy takes over within a few seconds. Copies started with `IMPROVE_WORKERS=0` never take it.
- **Restarts**: the queue is in `webui/improvements.json`; on start the owner requeues (once, with a note) any job that was running when the previous owner died, stopping its leftover agent. The first start of this code also requeued the jobs that older servers had wrongly marked "failed: server restarted ..." (they used to clear every queued job in the file on start, including other live servers' jobs). Jobs from an older server that is still running its own queue are left to it until it has been idle for 20 s.
- Run: `claude -p <prompt> --output-format stream-json --verbose --permission-mode bypassPermissions --strict-mcp-config --no-chrome --disallowedTools "Bash(git push:*)" ...`, cwd = the job's worktree (ROM: the ROM repo), 20 min timeout (the process group is killed). Poke-routes jobs get one MCP server, `routes` (`webui/route_tools.py`, stdlib, stdio, runs the worktree's own code); ROM jobs get none. The prompt (see `improve.py`) adds the repo's purpose, how to verify, the owner's rules from `documenting-agent-work/decisions.md` and `AGENT_BRIEF.md`, and hard limits: stay inside the worktree, no pushing, no remotes, no network-facing changes, no secrets.
- The server only listens on 127.0.0.1, and `/api/improve*` also checks `Host`/`Origin` and requires a JSON body, so another web page can't submit jobs through your browser.
- History: `webui/improvements.json` (+ `improvements.meta.json`: worker count, migration flag); logs and prompts: `webui/improve-logs/` (all gitignored). Each job also adds a line to `arklarna/documenting-agent-work/log/<date>.md`.
- If a job changes `webui/*.py`, restart the server to load it (static files and the generator reload on their own). Restarting is safe for the queue now: running jobs are re-run, queued ones wait.
- Testing on a throwaway clone: `IMPROVE_REPO=<clone> IMPROVE_STATE=<file> IMPROVE_WT_ROOT=<dir> IMPROVE_WORKLOG=0 PORT=8796 python3 webui/server.py`. Unit tests: `python3 -m unittest webui/tests/test_improve.py` (state machine, recovery, lock, merge with a conflict, memory guard, whole jobs with `tests/fake_claude.py`).
- **Agent** tab (next to Improve; also Window > Agent): for asking the tool to do something *for* you rather than change it, mostly tilesets ("get a DS-style autumn tileset", "use the PokeRoutes tiles for this route"), because the owner didn't want to learn the editor for that. It goes through the same queue (`mode: "agent"`), so it also ends in one commit with Undo; the prompt just adds a note on where the tilesets live and that new art has to come from its authors with a CREDITS.md. Its tasks also show up in the Improve history, marked "agent". Files: `static/agent.js`. Not tried on a real tileset download yet.
- **Route tools** for those runs (added after the owner asked for the agent to "just tool call things"): `list_specs`, `spec_fields`, `generate_route` (spec + seed + overrides -> tiled / plan / stage PNGs, report, Emerald files under `out/agent/<id>/`), `route_grid`, `paint_route` (set classes on cells or rectangles, re-tile), `generate_region`, `check_examples`. pokeroutes is re-imported on each generate, so generator edits made during the job count. Tried by hand over stdio and with `claude --mcp-config` (it connects and lists all seven); not yet watched in a real agent job, so whether it actually reaches for them is open.

API: `POST /api/improve {request, target, screenshot?, screenshots?}`, `GET /api/improve` (history, slots, owner), `GET /api/improve/<id>?since=N` (status + log lines), `POST /api/improve/<id>/undo`, `POST /api/improve/<id>/cancel`, `POST /api/improve/workers {workers}`.

## Region editor (rough)

`/editor.html` (also the Geography and Region tabs of the shell): the world map that `pokeroutes.region` generates, drawn on a canvas so it can be fixed by hand. Open with `?seed=N` or `?load=NAME`.

- Geography is generic per seed now (continent, coast, peninsula, islands, archipelago, inland lakes, crescent bay); the Geography select next to the seed forces a kind. A map starts with no towns: the owner places them, or Generate map places 4 to 14 (scaled with the land, at least one on every island big enough). `POST /api/editor/generate {seed, geography}`.
- Towns are placed by hand in Routes A: add town `T`, click on dry land, name it (default `Town 1`, `Town 2`...). Rename in the inspector, drag to move, `Del` or the inspector's Delete town button to remove. Adding or removing a town marks routes stale; recompute routes lays roads along the shortest tree between the towns (towns on landmasses farther apart than a short bridge get a Surf route over open sea). All of it is undoable and saved with the region. `POST /api/editor/add-town {doc, x, y, name}`, `POST /api/editor/delete-town {doc, id}`. Placing landmarks by hand isn't there yet.

- Draw route `D` (Map tab), freehand: drag to paint a route; the stroke snaps to straight horizontal / vertical runs and turns where the pointer turns (a wobble of one cell is ignored). Start or end anywhere: ending on open ground makes a dead end, every town or route the stroke touches joins in (one exit per touch, so passing through a route makes it a crossroads), and a stroke that only starts on open ground grows out of the place it reaches. Water never stops it: sea and lake stretches become sea (Surf) routes, short ones and rivers stay part of the land route. The only refusals are the map edge and a stroke that touches no town or route at all. Alt + drag erases drawn routes under the pointer, Esc cancels a stroke. The server (`pokeroutes/region/drawn.py`) cuts each piece of the stroke into route rects the same way searched links are (`Network._grow`), so exits, roles and specs work as usual. Drawn routes, and routes they touch, come back pinned; recompute keeps them and lays no second road between towns a drawn line already joins. Select a drawn route to drag its bends (the line is redrawn); `Del` removes the whole drawn line. `POST /api/editor/draw-route {doc, waypoints, legs?, replace?}`. No 45 degree runs: route rects are axis-aligned. Short land or sea stretches at the end of a stroke can come out as thin route rects.
- Town-map style (layer 6, on by default in Map and Story, off in Geography): an attempt at the Sinnoh town-map look, drawn on the client. Pale green land in height bands with relief and terrace rims (a step up casts a shadow on its south-east side), rivers as water bands on the grid that widen with their flow, light sea with a lighter halo along the coast, routes as peach bands with a darker outline (sea routes pale blue) that merge where they meet, towns as red rounded squares, landmarks as blue pills, special areas as mint blobs, labels in small dark text with a light outline. Height / biome / water toggles still work under it (they switch relief, biome tints and the coast halo). Turn it off for the old role-coloured route rects.
- Layers: hillshaded height, biomes, water (sea, lakes, rivers), routes (role colours; dashed border = unpinned), labels. Wheel or `+ - 0` to zoom, space / right / middle drag to pan.
- Tools (keys in brackets, `?` shows them all): select `V` (drag towns and landmarks, drag a selected route's edges or exits, double-click a route to open it in the bench), raise `R` / lower `L` / flatten `F` / smooth `S`, paint biome `B`, coast `W` (land / sea / lake), add route `A` (drag from a town or route to a town, route or landmark), add town `T`. `[ ]` brush size.
- Every edit marks the downstream stages stale. Recompute runs them on the server (`pokeroutes/region/edit.py`): water (lakes, rivers, flow), climate, biomes, routes. Hand-painted biome / coast cells are kept as overrides. Rivers can't be drawn any more (owner: compute them from the geography): the water stage routes rain, snowmelt and spring water downhill over the height and puts a river wherever enough gathers, so reshaping hills moves them. Old saved maps with hand-drawn rivers lose them on the next water recompute; pinned routes stay put and only the missing pieces of their links are re-laid. Editing a route (spec field, rect, exit, name, role) pins it.
- Route inspector: name, pin, role, biome, size, meander / branches / ... / special_area_chance / weather (hand-set values are marked `*` and can be reset), exits with a slider each, warnings (over the GBA budget, exits not flush, overlaps).
- Generated routes are just numbered, `Route 1`, `Route 2`... (map `MAP_ROUTE1`, which doesn't clash with Emerald's `MAP_ROUTE101`+). They used to get German compound names from biome + role ("Dünenhaken 2", "Felsbrück"); the owner called those trash. Renamed or pinned routes keep their name.
- Deleting a route drops its link from the plan and pins what's left of it, so recompute doesn't fill the gap back in.
- Undo / redo: 100 steps, copy-on-write grids. Save writes `region_out/<name>/region.json` (the usual summary plus an `editor` block with the whole document), `routes/*.yaml` and `region_map.png`; Load reads it back. Export specs downloads the same as a zip.
- Embeddable: `PREditor.init(container, opts)` in `static/editor/app.js` builds the editor inside any element and returns its actions (undo, redo, save, load, generate, exportSpecs, recompute, setTool, toggleLayer, fit, openInBench, destroy).
- Known gaps: Town-to-town links often find no free corridor because route rects may not overlap. Starting from a nearby route works better. A water recompute with no edits still shifts a few river cells, because rain follows the latest climate.

API: `POST /api/editor/{generate,load,recompute,add-route,draw-route,add-town,delete-town,save,spec,render,export}`, `GET /api/editor/list` (see `editor_api.py`).

## Bench paint

The **Paint** tool in the shell toolbar (`B`; **Stamp** is `S`) switches to the finished stage and paints from the left dock's **Tiles** tab, which is filled per route from `GET /api/paint-palette?id=` (`webui/paint_palette.py`): every class the route's tiler can draw (the PokeRoutes class table's letters including the autumn tall grass and orange/red forests, or the classes a learned model has at least 20 corpus cells of), each with a 2x2 sample tiled by that tiler; one ledge brush that `R` turns through the tileset's ledge directions; objects (PokeRoutes props such as stump, log, fence, boulder, flowers, split oak, with their own collision; General trees, pine, Fortree round tree and flowers for the learned tilesets, plus the class stamps); and every exact metatile at the bottom. Classes the tiler can't draw are listed under the grid with what they would turn into. Tree and water strokes are at least 2 wide; on the PokeRoutes tiler tree strokes snap to whole even-aligned 2x2 blocks, because a tree off that grid comes out as bushes (that, plus no tree brush at all on PokeRoutes, was why trees could not be painted). Each stroke gets the generator's cleanup around it (1-wide tree walls left behind become grass, lone water cells become grass). `POST /api/retile` re-tiles with the same tiler, keeping every metatile whose 3x3 class neighbourhood didn't change; object and exact cells arrive as a class plus `#metatile`, a blocked object cell is class `o`, and blocked ones get collision in the layout, so the Porymap export zip carries them. Paint is remembered per route name and size (localStorage `pokeroutes-paint-v1`) and put back on page load; Generate starts a fresh map. Strokes are undoable with Cmd/Ctrl+Z.

Tests: `node webui/tests/editor-logic.test.js` (pure editor logic: grids, brushes, undo/redo, route edits) and `node webui/tests/shell-logic.test.js` (shell: shortcuts, layout, undo, paint memory, palette brushes); `python3 -m pytest -q webui/tests/test_paint_palette.py` (palette per tiler, object cells).

## Tile editor (rough)

**Window > Tools > Tile editor** opens a floating window over the shell (drag its title bar, resize from the corner, the title-bar button or a double-click docks it over the centre views and back). It is a first pass at drawing on the tiles themselves, not a finished pixel editor.

- Left: every metatile of the chosen tileset at 2x (primary, a gap, then secondary); a yellow corner marks new or edited ones, the star shows only those. `+` makes a blank tile, the copy button duplicates the selected one. Arrow keys walk the sheet.
- Centre: the selected 16x16 metatile with its 2x2 8x8 tiles; Bottom/Top (`T`) picks the layer you draw on, the other one is shown faded. Tools: pencil `B` (right-click picks a colour), fill `G`, eyedropper `I`, line `L`, mirror left/right `X` and top/bottom `Y`, flip, rotate `R` (both layers), and the link toggle to draw on shared 8x8 tiles in place. Without it, the first stroke on a tile that other metatiles also use copies it to a free slot (secondary sheet: appended up to 512; primary: blank unused slots), so one edit never leaks into another metatile. Zoom with `-`/`+` or Cmd/Ctrl+wheel; undo/redo with Cmd/Ctrl+Z / Shift+Cmd/Ctrl+Z.
- Right: the 16 colours of the highlighted 8x8 quarter's palette (the palette menu re-palettes that quarter), the selected colour's value (snapped to GBA 15-bit; editing it changes that palette slot for every tile using it), live 1x/2x/4x previews and a 3x3 tiling for seams, then behaviour and layer type, and "Paint palette": a tile with that ticked shows up under Objects in the Tiles tab with its name, class and Blocked flag.
- Save (`Cmd/Ctrl+S`) writes `tilesets/overrides/ark/overlay.json` (gitignored, in the main checkout, shared by every worktree; `POKEROUTES_TILE_OVERRIDES` moves it). The ROM tree is never written. The previous overlay is kept as `overlay.previous.json`. Each save bumps a revision; if the agent or another tab saved in between, Save says so and offers Reload instead of overwriting. Revert goes back to the last save (undoable).
- After a save, Generate: the Ark tiler, the atlas, the paint palette and the Porymap export all read the overlay (`ArkTiler.load`, `ArkTiler.pair`). The export zip then also carries `data/tilesets/{primary/ark_outdoor,secondary/ark_woodland}` with the edits applied (tiles.png, palettes, metatiles.bin, metatile_attributes.bin).
- Emerald (learned) tilesets open read-only.
- Not done yet: an **Export to ROM** action. For now copy the `data/tilesets/...` folders from a Porymap export zip into the ROM tree by hand (`write_overlaid_tileset_pair_files` in `pokeroutes/tileset_overlay.py` writes them). New metatiles past the ROM's count also need the class table (`metatile_classes_ark.json`) and the tileset build script updated on the ROM side. Tile animations (water, flowers) aren't editable, and an edited animated tile shows its static frame.

API (`webui/tile_overrides.py`): `GET /api/tile-editor/tilesets`, `GET /api/tile-editor/tileset?id=ark` (ROM tiles, palettes, metatiles plus the overlay), `POST /api/tile-editor/edit {id, overlay, operation}` (applies one edit to a draft, saves nothing), `POST /api/tile-editor/save {id, overlay, revision}` (409 on a stale revision). The edits themselves are in `pokeroutes/tile_editing.py` (pixels, copy-on-write, flips, palettes, new tiles, properties), `pokeroutes/tile_coalesce.py` (edge sets) and `pokeroutes/tile_operations.py` (the dispatcher both the API and the agent use). Front end: `static/tile-editor.js`, `static/tile-editor-logic.js` (pure), `static/tile-editor.css`.

Agent tools (`webui/tile_agent_tools.py`, in the routes MCP server): `tile_sheet` (labelled sheet PNG), `tile_read` (one metatile as hex rows plus a preview), `tile_edit {operation}` (the same operations as the API, saved at once), `tile_coalesce {inner, outer, class}`: draws the 47 blob variants of a terrain fading into a surrounding tile (a 3 px band of the outer tile on open sides, a darker outline, rounded corners, built per 8x8 quarter so it needs at most 16 new tiles) and registers them as a blob class in the overlay, so the Ark tiler draws that letter (e.g. `d` sand, which otherwise falls back to path) and the Tiles tab offers it.

Tests: `python3 -m pytest -q webui/tests/test_tile_overrides.py`, `node webui/tests/tile-editor-logic.test.js`.
